    Why should I care?

    Not every failure
    needs reasoning.

    Payment failures are not all equally difficult. Some need reasoning. Others are situations the system has already seen.

    LLMs are useful for ambiguous decisions, but calling one again and again for the same known situation adds latency, cost and variability.

    This agent uses the LLM where reasoning helps and deterministic rules where the behavior has already been validated, while keeping the LLM available for cases that still need it.

    What makes this different?

    Teach once.
    Execute deterministically.

    Most AI agents call an LLM whenever they need to decide. This project goes the other way: use the LLM for ambiguity, validate what worked, turn it into a deterministic rule, and let that rule handle future matching cases.

    This is not fine-tuning: the model is never retrained. "Self-distilling" means validated agent behavior becomes an executable rule, stored as data, that can be promoted, monitored and demoted.

      What just happened?+

      First, the system checks whether it already knows how to handle this payment failure. If a validated rule exists, the rule handles it without calling the LLM. If no rule matches, the LLM handles the ambiguous case. Successful behavior can later become a deterministic rule.

      Why does this matter?

      Repeated LLM reasoning can be replaced by validated deterministic behavior for cases the system has already learned.
